# Polymarket Multi-Agent Trading Bot

Автоматическая торговая система для Polymarket (рынки предсказаний на Polygon).
Работает **без выделенного VPS** — исполняется как задача по расписанию в
GitHub Actions (бесплатно в рамках лимитов) каждые ~30 минут.

## Как это работает

1. GitHub Actions по крону запускает `python -m src.main` — один полный цикл.
2. Бот забирает активные рынки через публичный Gamma API Polymarket.
3. Четыре независимых агента анализируют рынки:
   - **Momentum** — резкое движение цены за последний час
   - **Volume Spike** — аномальный объём относительно ликвидности
   - **Arbitrage** — сумма цен исходов бинарного рынка отклоняется от 100%
   - **Sentiment** — Claude API формирует независимую оценку вероятности и
     сравнивает с рыночной ценой (самый дорогой по токенам агент — ограничен
     `max_sentiment_calls_per_cycle` в конфиге)
4. `PortfolioCoordinator` агрегирует сигналы: если несколько агентов
   согласны — уверенность растёт; если противоречат — гасят друг друга.
5. `RiskManager` проверяет жёсткие лимиты (см. `config.yaml`) и либо
   урезает размер позиции, либо отклоняет сделку целиком.
6. Если `dry_run: true` — сделка только логируется. Если `false` — реальный
   ордер отправляется через `py-clob-client`.
7. Состояние (открытые позиции, дневной P&L) сохраняется в `data/state.json`
   и коммитится обратно в репозиторий — это то, что заменяет постоянно
   работающий сервер.

## Стоимость

- **Хостинг: $0.** GitHub Actions даёт 2000 бесплатных минут/месяц на
  приватных репо (публичный репо — не ограничено). Один цикл занимает
  ~10-30 секунд, 30-минутный интервал = ~1500 запусков/месяц × ~20 сек ≈
  8 часов = укладывается с большим запасом.
- **Токены Claude API: зависит от `max_sentiment_calls_per_cycle`.** При
  лимите 8 рынков/цикл и запуске каждые 30 минут это ~384 вызова/день.
  Держите этот параметр небольшим и увеличивайте только если бюджет
  позволяет — это единственная статья реальных расходов в системе.

## Установка

### 1. Кошелёк

Создайте **отдельный** кошелёк на Polygon специально для бота (не основной!).
Переведите на него небольшую сумму USDC (нативный на Polygon, не
USDC.e) — столько, сколько готовы потерять на старте. Убедитесь, что
Polymarket доступен в вашей юрисдикции — есть гео-ограничения и KYC на
вывод, уточните это на polymarket.com перед тем как заводить капитал.

### 2. Клонировать репозиторий и поставить зависимости

```bash
git clone <ваш форк этого репо>
cd polymarket-bot
pip install -r requirements.txt
cp .env.example .env
```

Впишите `POLYGON_PRIVATE_KEY` и `ANTHROPIC_API_KEY` в `.env`.

### 3. Получить CLOB API-креды (один раз)

```bash
python scripts/setup_clob_creds.py
```

Впишите выведенные `CLOB_API_KEY` / `CLOB_API_SECRET` / `CLOB_API_PASSPHRASE`
в `.env`.

### 4. Тестовый прогон локально (dry-run)

```bash
python -m src.main
```

Проверьте `data/run.log` — какие сделки бот бы совершил.

### 5. Настроить GitHub Actions

В настройках репозитория → Settings → Secrets and variables → Actions
добавьте секреты:
- `POLYGON_PRIVATE_KEY`
- `CLOB_API_KEY`, `CLOB_API_SECRET`, `CLOB_API_PASSPHRASE`
- `ANTHROPIC_API_KEY`

Запушьте репозиторий — workflow `.github/workflows/trade.yml` начнёт
выполняться по расписанию (и его можно запустить вручную вкладке Actions →
Run workflow).

### 6. Переход от dry-run к реальным сделкам

Не спешите. Дайте боту поработать в `dry_run: true` минимум несколько дней,
посмотрите на `data/trade_log` в state.json — какие сделки он бы делал и
насколько разумны причины (`reasoning`). Только после этого меняйте
`config.yaml`:

```yaml
mode:
  dry_run: false
```

## Управление риском

Всё в `config.yaml` под `risk:`. Стартовые значения консервативны:
2% риска на сделку, 10% максимум одновременно, дневной стоп-лосс 8%.
`kill_switch: true` в конфиге мгновенно останавливает торговлю независимо
от всего остального — используйте, если что-то пошло не так.

## Важно понимать

- Это **не финансовый совет** и не гарантия прибыли — сигналы основаны на
  эвристиках и оценках Claude, которые могут ошибаться.
- Агент Sentiment опирается на общие знания модели, а не на живые новости
  в реальном времени — для быстро меняющихся событий это ограничение.
- GitHub Actions cron не даёт гарантии секундной точности — при высокой
  нагрузке платформы запуск может задержаться на несколько минут.
- Начинайте с суммы, потерю которой вы готовы принять безболезненно.
